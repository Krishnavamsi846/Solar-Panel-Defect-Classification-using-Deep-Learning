## Project Overview

This project investigates **six-class image-level classification of visible photovoltaic (PV) panel conditions** using ordinary RGB images.

Three deep-learning models were compared under the same leakage-controlled experimental protocol:

- **ResNet-50**
- **EfficientNet-B0**
- **YOLOv8 Classification**

The project evaluates not only overall predictive performance, but also:

- class-wise precision, recall and F1-score;
- balanced accuracy and macro-F1;
- confusion matrices;
- ROC-AUC and precision-recall behaviour;
- prediction confidence and calibration;
- model size and inference latency;
- high-confidence misclassification patterns.

The final system is an **academic decision-support prototype**. It predicts one condition for the complete image. It does **not** localise defects with bounding boxes, identify hidden electrical faults, or replace a qualified PV inspection.

---

## Research Objective

The main objective is to determine how effectively deep-learning models can classify visible solar-panel conditions and identify which of **ResNet-50, EfficientNet-B0 and YOLOv8 Classification** provides the strongest balance between:

1. predictive performance;
2. class-level reliability;
3. probability confidence;
4. computational efficiency; and
5. practical prototype suitability.

## Data Quality Audit

A major part of the project was controlling duplicate-image leakage before model training.

| Data-audit stage | Images |
|---|---:|
| Original image files | 1,574 |
| Cross-class conflicting files excluded | 8 |
| Same-class exact duplicate copies removed | 697 |
| Unique valid images retained | **869** |

Exact file content was checked using **SHA-256 hashes**.

Duplicate and conflicting images were handled **before** the final data split so that exact copies could not appear in both training and evaluation partitions.

### Final Stratified Split

| Partition | Images |
|---|---:|
| Training | 695 |
| Validation | 87 |
| Held-out test | 87 |
| **Total** | **869** |

A fixed random seed of `42` was used for repeatability.

The notebook also verifies that the final train, validation and test partitions contain **zero exact SHA-256 hash overlap**.

## Preprocessing Pipeline

The final preprocessing workflow includes:

1. locating all approved image files;
2. checking that images are readable;
3. computing SHA-256 hashes;
4. identifying cross-class exact conflicts;
5. removing exact same-class duplicate copies;
6. creating the unique-image manifest;
7. creating a stratified `80:10:10` train/validation/test split;
8. confirming zero exact hash overlap across partitions;
9. resizing images to `224 x 224`;
10. applying the input normalisation required by the pretrained models;
11. applying augmentation **only to the training set**;
12. applying imbalance handling only during training;
13. keeping validation and test transforms deterministic.

### Training Augmentation

Training-time augmentation includes mild image transformations such as:

- random resized cropping;
- horizontal flipping;
- small rotations;
- limited colour / brightness variation.

Validation and test images are **not randomly augmented**.

## Models

### 1. ResNet-50

ResNet-50 is a deep convolutional neural network that uses **residual / skip connections**.

These connections allow information and gradients to bypass some layers, helping deep networks train more reliably.

**Role in this project:** strong conventional CNN transfer-learning benchmark.

### 2. EfficientNet-B0

EfficientNet uses a balanced scaling strategy across network depth, width and image resolution.

**Role in this project:** compact transfer-learning model used to investigate the accuracy-efficiency trade-off.

### 3. YOLOv8 Classification

The project uses **YOLOv8 in classification mode**, not object-detection mode.

The model receives a complete image and returns probabilities over the six PV-condition classes.

**Role in this project:** modern visual classifier evaluated for predictive performance, model size and inference efficiency.

Because the dataset contains image-level labels rather than bounding boxes, **classification** is the appropriate task.

## Training Design

### ResNet-50 and EfficientNet-B0

The PyTorch models use:

- ImageNet-pretrained weights;
- a six-class classification head;
- staged / transfer-learning fine-tuning;
- training augmentation;
- class-weighted cross-entropy where configured;
- validation monitoring;
- best-checkpoint restoration.

### YOLOv8 Classification

The YOLO workflow uses:

- a pretrained YOLOv8 classification checkpoint;
- training-only augmentation;
- training-only oversampling for imbalance handling;
- best validation checkpoint selection;
- saved Ultralytics run artefacts in `yolo_runs/`.

---

## Model Selection Rule

The final model was selected using **validation data only**.

The primary criterion was:

> **Validation macro-F1**

Macro-F1 was chosen because each of the six classes receives equal importance even when class frequencies differ.

Efficiency evidence such as model size and inference latency was also considered.

The held-out test set was **not used to choose the model**.

## Final Results

### Held-Out Test Performance

| Model | Accuracy | Macro-F1 |
|---|---:|---:|
| **YOLOv8 Classification** | **87.36%** | **0.8626** |
| ResNet-50 | 82.76% | 0.8159 |
| EfficientNet-B0 | 77.01% | 0.7501 |

### Selected YOLOv8 Classification Model

| Metric | Result |
|---|---:|
| Validation macro-F1 | **0.8995** |
| Test accuracy | **0.8736** |
| Test balanced accuracy | **0.8558** |
| Test macro-F1 | **0.8626** |
| Test weighted-F1 | **0.8707** |
| Expected Calibration Error | **0.102** |
| Checkpoint size | **~30.23 MB** |
| Median measured inference time | **~19.18 ms/image** |

Inference time depends on the hardware, software environment and measurement procedure.

## Class-Level Findings

The selected YOLOv8 Classification model performed particularly well on:

- `Snow-Covered`
- `Electrical-damage`
- `Clean`

The main weakness was:

- `Physical-Damage`

Some misclassifications occurred between visually overlapping conditions such as:

- `Bird-drop`
- `Dusty`
- `Physical-Damage`

The project therefore reports class-level evidence rather than relying only on overall accuracy.

## Evaluation Metrics

The project uses:

- **Accuracy** - overall proportion of correct predictions.
- **Precision** - how many predictions for a class were correct.
- **Recall** - how many real examples of a class were found.
- **F1-score** - harmonic mean of precision and recall.
- **Macro-F1** - equal-weight average F1 across all six classes.
- **Weighted-F1** - class F1 weighted by class support.
- **Balanced Accuracy** - average recall across classes.
- **Confusion Matrix** - class-by-class error analysis.
- **ROC-AUC** - one-vs-rest class-ranking performance across thresholds.
- **Precision-Recall analysis** - useful under class imbalance.
- **Expected Calibration Error** - confidence calibration quality.
- **Inference latency and checkpoint size** - computational efficiency.

## Limitations

The main limitations are:

- only **869 unique valid images** remained after data-quality control;
- the held-out test set contains **87 images**;
- some classes contain relatively few test images;
- the test images come from the same overall source collection;
- visually similar conditions can be difficult to separate;
- background, brightness and framing may create shortcut-learning risks;
- independent multi-site field generalisation has not been established;
- the task is **single-label image classification**, not localisation;
- unseen conditions are not represented by an explicit `Unknown` class;
- probability calibration is imperfect;
- no human-participant user acceptance study was conducted under the approved no-participant ethics scope.

The results should therefore be interpreted as evidence for an **academic research prototype**, not proof of industrial deployment readiness.
